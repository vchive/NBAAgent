# COURTSIDE NBA UI Demo

这是一个零依赖的前端展示页，用本地 fixture 模拟 NBA Chat Agent 的 SSE 事件，不需要
Node、构建工具或任何 API 凭据。页面包含比赛 HUD、聊天流式状态、事实卡片、表格和
逐回合回放。

## 启动

在仓库根目录执行：

```bash
python3 -m http.server 4173 --directory apps/web-demo
```

浏览器打开 <http://localhost:4173>。

也可以使用任意静态文件服务器托管该目录。输入问题时，页面会离线模拟以下交互：

- 普通 NBA 问题：阶段状态 → 增量回答 → 已核验卡片/表格；
- “最后 5 秒 / 关键回合”：同时展示 Q4 PBP 表格并可在右侧回放；切到 OT 会展示本场无加时的空状态；
- “战术 / 复盘”：事实和分析分色区分；
- “核验 / 记得”：展示礼貌纠偏；
- “博彩 / 下注”等红线：只展示安全提示；
- 输入“断线”或“超时”：展示可重试错误卡片；
- “新对话”：清理当前页面消息并生成隔离的 session id。

## 交互路径

1. 用户从左侧快捷问题或底部输入框发起问题；`Enter` 发送，`Shift + Enter` 换行。
2. 中央时间线先显示用户消息和生成占位符，再依次展示“解析 → 核对 → 核验 → 整理”
   状态，最后将草稿替换成结构化回答。
3. 回答中的事实卡片、表格、分析、纠偏、暂无数据和安全提示使用不同视觉层级；底部
   显示证据状态和北京时间口径。
4. 右侧 HUD 与聊天共用同一场 fixture。切换节次、点击事件、拖动滑块或播放回放时，
   事件选中态、比分和比赛时钟同步更新；没有事件的 OT 会显示明确空状态；“按序回放 ·
   非视频”明确当前是 PBP 定位。
5. 生成中可以点击停止；失败卡片可重试（演示第二次以同一幂等键模拟恢复）；“新对话”
   会清理动态消息并隔离新的 `session_id`。

## 视觉结构

- 深色竞技场底色 + 细网格和玻璃卡片，使用青色（系统动作）、绿色（已核验）、橙色
  （分析）和红色（错误/红线）作为状态色。
- 三栏桌面布局：左侧赛事导航和问题入口，中间聊天主舞台，右侧比分 HUD / PBP / 口径
  说明；窄屏按“问题入口 → 聊天 → HUD”顺序堆叠。
- 所有内容均为自绘 CSS/SVG，不引入 NBA 或赛事官方 Logo、字体和受版权限制的素材。

真实服务接入时，可保留 `AnswerBlock` 渲染器和 `CourtsideSSEParser`，将
`startDemoRun` 替换为 `fetch('/api/v1/chat/stream', { method: 'POST' })` 的
`ReadableStream` 消费逻辑即可。
