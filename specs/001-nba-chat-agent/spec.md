## Scope and source notes

本规格将 PDF 中可识别的题目要求拆分为可验收需求。PDF 共 4 页，主题为 NBA Chat Agent，覆盖 NBA 数据获取、自然语言问答、Agent 工具调用、结果展示和评测。PDF 的部分中文字体编码异常，未能可靠还原的实现细节列为假设或后续决策，不作为已确认要求。

## User Scenarios & Testing

### User Story 1 - 查询 NBA 信息 (Priority: P1)

用户用自然语言询问球员、球队、比赛、赛程、排名或统计数据，并获得直接答案。

**Why this priority**: 这是题目要求的核心用户价值，也是最小可用产品。

**Independent Test**: 使用至少 10 个覆盖不同问题类型的 NBA 问题测试，答案应包含对应实体和数据，并能追溯到数据来源。

**Acceptance Scenarios**:

1. **Given** 数据源可用，**When** 用户询问指定球员或球队信息，**Then** Agent 返回结构化、易读的相关信息。
2. **Given** 用户询问某场比赛结果或赛程，**When** 问题包含球队、日期或赛季条件，**Then** Agent 返回匹配的比赛记录及日期/状态。
3. **Given** 用户询问排名或统计数据，**When** 问题包含统计口径和时间范围，**Then** Agent 明确口径并返回结果。

### User Story 2 - 多轮追问与条件补全 (Priority: P2)

用户可以在上一轮结果基础上继续追问，Agent 保留必要上下文；当条件不足时，Agent 主动请求补充。

**Why this priority**: 题目定位为 Chat Agent，而非单轮搜索框。

**Independent Test**: 先询问球队，再使用“这支球队最近五场如何”等省略主语的问题进行追问，验证上下文解析和结果正确性。

**Acceptance Scenarios**:

1. **Given** 上一轮已确定球队或球员，**When** 用户使用代词或省略实体追问，**Then** Agent 使用当前会话上下文回答。
2. **Given** 问题缺少决定性条件，**When** Agent 无法唯一确定答案，**Then** Agent 询问最少的补充信息，不编造结果。

### User Story 3 - 数据来源与异常反馈 (Priority: P2)

用户能够看到答案的数据时间或来源；外部数据不可用、无匹配结果或问题超出 NBA 范围时，获得明确反馈。

**Why this priority**: NBA 数据具有时效性，可靠性和可解释性是评测重点。

**Independent Test**: 模拟接口超时、空结果、限流和非 NBA 问题，验证每种场景都有可理解的提示。

**Acceptance Scenarios**:

1. **Given** 外部数据源失败或超时，**When** 用户发起查询，**Then** Agent 返回暂不可用提示，并建议重试，不输出未经验证的数据。
2. **Given** 查询无匹配记录，**When** 用户提交问题，**Then** Agent 说明无结果并给出可调整的查询条件。
3. **Given** 问题不属于 NBA 范围，**When** 用户提交问题，**Then** Agent 礼貌说明范围并引导用户提出 NBA 问题。

### Edge Cases

- 日期未注明时区时，系统使用项目约定时区并在答案中注明日期口径。
- 赛季、日期、球队或球员名称存在歧义时，系统先列出候选或请求澄清。
- 数据源返回部分字段、重复记录或字段格式异常时，系统标记缺失信息，不以默认值冒充真实数据。
- 接口限流、网络错误和响应超时必须可观测且不导致会话崩溃。
- 用户连续快速发起请求时，系统应避免重复调用或明确提示限流。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 接收自然语言 NBA 查询并返回自然语言答案。
- **FR-002**: 系统 MUST 支持球员、球队、比赛、赛程、排名和统计数据六类问题。
- **FR-003**: 系统 MUST 从问题中识别实体、指标、赛季、日期和其他筛选条件。
- **FR-004**: 系统 MUST 在需要实时或结构化数据时调用配置的数据源，并将查询结果转换为用户可读内容。
- **FR-005**: 系统 MUST 对答案中的关键数据标注数据来源或数据更新时间。
- **FR-006**: 系统 MUST 支持基于当前会话的上下文追问，并避免跨会话混淆上下文。
- **FR-007**: 系统 MUST 在条件不足、实体歧义或无结果时向用户提出澄清或调整建议。
- **FR-008**: 系统 MUST 对超时、限流、认证失败、数据格式错误和服务不可用提供明确错误提示。
- **FR-009**: 系统 MUST 拒绝或引导不属于 NBA 范围的问题，不得伪造 NBA 数据。
- **FR-010**: 系统 MUST 记录查询、数据源调用、耗时、错误类型和最终状态，且不得记录不必要的敏感信息。
- **FR-011**: 系统 MUST 提供可重复运行的示例问题和验收方式。
- **FR-012**: 系统 MUST 提供项目启动、配置、数据源和限制说明。
- **FR-013**: 系统 MUST 使用明确的时间和时区规则；默认展示时间采用 UTC+8，除非用户明确指定其他时区。
- **FR-014**: 系统 MUST 将数据访问逻辑与对话编排逻辑分离，使数据源可替换和独立测试。

### Key Entities

- **球员**：姓名、唯一标识、所属球队及可查询统计。
- **球队**：名称、唯一标识、赛季、战绩和排名。
- **比赛**：比赛标识、日期时间、主客队、比分、状态和赛季。
- **统计指标**：指标名称、数值、统计对象、统计范围和更新时间。
- **用户查询**：原始问题、解析条件、会话标识、查询时间和处理状态。
- **数据来源**：来源名称、请求参数、响应时间、更新时间和错误状态。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 10 个基准问题中至少 8 个返回正确实体、时间范围和核心数值。
- **SC-002**: 正常数据源条件下，90% 的查询在 5 秒内返回首个完整答案。
- **SC-003**: 100% 的外部数据失败、空结果和歧义场景返回明确提示，不生成无来源数据。
- **SC-004**: 至少覆盖球员、球队、比赛、赛程、排名、统计六类问题，并为每类提供示例。
- **SC-005**: 新开发者按照 README 在干净环境中能够完成配置并启动示例。
- **SC-006**: 评测者能够从日志或展示结果确认每次查询的数据来源、时间口径和处理状态。

## Assumptions

- v1 面向中文用户，优先支持中文自然语言问题；英文实体名作为兼容输入。
- v1 以公开 NBA 数据源为依赖，具体供应商、凭据和配额在规划阶段确定。
- v1 不包含账号体系、付费订阅、赛事直播和 NBA 之外的通用问答。
- 数据源的访问凭据通过环境变量或本地配置注入，不提交到仓库。
- 题目中的评测表由项目示例和自动化测试共同覆盖；最终评分口径以 PDF 原题为准。
