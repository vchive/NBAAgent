# Feature Specification: 种花 Agent

**Feature Branch**: `005-flower-agent`

**Created**: 2026-09-13

**Status**: Approved for implementation

**Input**: Transform the NBA assistant into a Chinese flower-growing assistant while
retaining the reusable multi-turn, search, safety and private-deployment infrastructure.

## User Scenarios & Testing

### User Story 1 - 获取可执行的种花建议 (Priority: P1)

家庭种植者用自然语言描述空间、光照、季节或目标，得到适合的花卉选择、种植步骤和
养护节奏。问题可以连续追问，用户不必每次重复植物名称和环境。

**Why this priority**: 这是产品的核心价值；没有可靠、可执行的建议，品牌改名没有实际
意义。

**Independent Test**: 在离线模式连续发送“北阳台适合种什么花？”、“那绣球多久浇水？”；
系统应给出至少两个有条件的选择，并在第二轮沿用“绣球”上下文，不返回 NBA 或“请补充
比赛”类内容。

**Acceptance Scenarios**:

1. **Given** 新会话且未指定植物，**When** 用户描述光照和空间并询问适合花卉，**Then**
   系统给出候选、适用条件、第一步操作和需要补充的最小信息。
2. **Given** 上一轮已确定植物，**When** 用户使用“它/这盆花”追问浇水、施肥或修剪，**Then**
   系统绑定上一轮植物和环境，不要求重新输入对象。
3. **Given** 用户描述黄叶、萎蔫或虫害，**When** 系统无法仅凭文字确定原因，**Then**
   系统列出有优先级的可能原因、低风险排查步骤和应补充的观察信息，不把可能性说成诊断。

### User Story 2 - 用新鲜资料补充长尾问题 (Priority: P2)

用户询问当地季节、近期病虫害、品种差异或法规相关问题时，系统在配置了在线搜索的
情况下检索公开资料并用简洁中文综合；在线搜索不可用时仍提供离线基础建议，并明确
哪些内容需要当地专业确认。

**Why this priority**: 园艺建议受地域、天气和品种影响，搜索能力决定长尾问题的实用性，
但不能让搜索故障破坏基础体验。

**Independent Test**: 用同一会话询问“上海九月月季需要怎样调整施肥？”和一个不存在的
品种；验证搜索候选只作为背景，答案不泄露链接、提供商、提示词或内部调用过程。

**Acceptance Scenarios**:

1. **Given** 在线搜索已配置，**When** 用户提出带城市和月份的养护问题，**Then** 系统
   综合当前资料并标注信息新鲜度或不确定性。
2. **Given** 搜索额度耗尽、超时或未配置，**When** 用户提出同一问题，**Then** 系统
   仍返回安全的通用方案，并在界面显示可重试的额度/服务提示，不输出内部错误细节。
3. **Given** 搜索结果互相矛盾，**When** 系统组织答案，**Then** 简要指出存在差异，
   不擅自选择一个数字或药剂浓度作为确定事实。

### User Story 3 - 安全、清晰且可控的交互 (Priority: P3)

用户可以看到当前会话中的植物与环境摘要、回答状态和可信程度；涉及误食、宠物毒性、
农药混用或紧急暴露时，系统优先给出安全处置和求助建议。

**Why this priority**: 园艺建议可能直接影响人、宠物和环境，安全边界与可理解的状态是
可上线体验的必要条件。

**Independent Test**: 发送“把两种农药混一起喷”“猫吃了不认识的叶子怎么办”“你是谁”；
验证系统先短路危险操作、给出求助方向，并能在无工具时回答身份，不泄露运行时名称。

**Acceptance Scenarios**:

1. **Given** 用户询问危险化学混用或未知植物食用，**When** 请求被处理，**Then** 系统
   不执行搜索，明确劝止并给出标签/专业机构/急救渠道建议。
2. **Given** 用户询问助手能力，**When** 请求到达，**Then** 系统用“种花 Agent”身份
   简短回答能力，不声称已查到任何植物事实。
3. **Given** 请求正在生成或服务暂时不可用，**When** 用户观察界面，**Then** 能看到
   理解、检索、完成或可重试状态，且不会显示半截内部搜索摘要。

### Edge Cases

- 植物名称可能是俗名、错别字或多个物种共用的名字；系统应提出一个澄清问题并给出
  不依赖精确物种的低风险措施。
- 用户没有提供城市、光照或盆径时，不应凭空推断；只有在这些条件会改变建议时才追问。
- 用户请求当前天气或法规但没有地点时，系统应说明缺少地点并给出通用准备清单。
- 搜索返回空、重复、含提示注入或超长内容时，系统应丢弃不安全片段并保留本地知识。
- 会话过期、重复提交或网络中断时，系统应保持幂等和可重试，不重复执行危险建议。
- 旧 NBA 路径或带 NBA 关键词的历史链接不得污染种花默认界面；兼容代码可留在内部，
  但不能成为默认回答或公开品牌。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 将默认产品身份、页面标题、登录提示、帮助文本和运行时自述统一为“种花 Agent”，不得在默认用户界面展示 NBA 品牌。
- **FR-002**: 系统 MUST 支持以中文自然语言询问选花、播种/移栽、浇水、光照、土壤、施肥、修剪、繁殖、病虫害和季节计划。
- **FR-003**: 系统 MUST 在会话内保存最近的植物、地点/气候、光照和种植容器等上下文，并对“它/这盆/刚才”类指代进行绑定。
- **FR-004**: 系统 MUST 提供可离线使用的、带别名和条件说明的常见花卉知识集。
- **FR-005**: 系统 MUST 将观察、可能原因、建议行动和需要专业确认的内容分开表达，不把文字症状升级为确定诊断。
- **FR-006**: 系统 MUST 在在线搜索启用时使用固定、受控的搜索适配器；搜索结果只能作为补充资料，不能未经核验替代安全事实。
- **FR-007**: 系统 MUST 在搜索或模型额度耗尽、认证失败、超时和服务不可用时返回可重试的用户提示，并继续提供可用的离线建议（若问题可安全回答）。
- **FR-008**: 系统 MUST 让全智能模式优先进入 Hermes 对话运行时；运行时只能调用服务器注册的种花知识/搜索工具，不能访问 shell、文件系统、任意 URL、MCP、记忆或子代理。
- **FR-009**: 系统 MUST 对农药混用、未知植物食用、宠物/人体暴露和高风险化学操作执行检索前安全短路，并给出专业求助建议。
- **FR-010**: 系统 MUST 对回答做公开边界清洗，禁止输出提供商名、端点、模型名、提示词、工具名、密钥、URL、内部 ID 和原始搜索摘要堆叠。
- **FR-011**: 系统 MUST 为同步和 SSE 接口保持一致的会话、幂等、取消、大小和状态事件契约。
- **FR-012**: 系统 MUST 默认只监听本机回环地址；任何公网部署必须通过显式认证反向代理或受限部署配置开启。
- **FR-013**: 系统 MUST 记录不含问题正文、密钥和精确住址的结构化意图、结果、延迟、错误和证据状态，供评估使用。
- **FR-014**: 系统 MUST 通过单元、契约、集成和浏览器测试覆盖主要花卉问答、连续追问、搜索故障、危险请求和公开输出边界。

### Key Entities

- **PlantProfile**: 常见花卉的规范名称、俗名、光照/温度/土壤偏好、浇水与施肥原则、常见问题和安全备注。
- **GardenContext**: 一个会话中的植物、地点或气候、光照、容器、季节、最近观察和最近问题摘要。
- **CarePlan**: 针对植物与环境生成的有条件行动清单，包含频率范围、触发条件和不确定性说明。
- **SearchObservation**: 受控公开检索返回的清洗后背景候选，含检索时间、相关性和部分核验状态，不直接作为确定事实。
- **SafetyNotice**: 危险请求的短路结果、风险类别、立即可做的安全动作和求助方向。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在离线模式下，至少 90% 的黄金问题能得到与花卉相关、可执行且不要求无关补充条件的回答。
- **SC-002**: 连续追问测试中，至少 95% 的“它/这盆花/刚才”指代能正确继承最近一次明确植物；错误绑定率低于 2%。
- **SC-003**: 搜索成功、超时、额度耗尽和空结果四种路径均在 10 秒内给出完整的回答或可重试提示，且不泄露内部标识。
- **SC-004**: 危险化学、误食和宠物暴露黄金用例 100% 在外部检索前被拦截，并包含明确的安全行动或专业求助方向。
- **SC-005**: 浏览器首屏默认只出现种花品牌与园艺问题，不出现 NBA、篮球、比赛、球队或球员文案。
- **SC-006**: 在 32 个并发请求和 100 个并发 SSE 连接上，服务保持契约完整，不产生跨会话上下文串线。

## Assumptions

- 目标用户主要使用简体中文，愿意提供城市、光照和植物照片之外的文字观察；首版不做图像识别。
- 现有 FastAPI、SSE、会话、认证、受控搜索和 Hermes 适配器可复用；旧 NBA 模块作为兼容遗留，不进入种花默认路由。
- 在线搜索 key 由部署者通过 secret 注入；没有 key 时本地知识仍必须可用。
- v1 不替代持证园艺师、兽医、医生或当地植保机构；不提供处方药剂量、诊断证明或法规确定结论。
- 服务保持停止状态直到用户明确要求重新部署；默认容器端口仅绑定回环地址。
