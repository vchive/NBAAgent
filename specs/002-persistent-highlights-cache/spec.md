# Feature Specification: 赛事回顾持久缓存与完整性

**Feature Branch**: `002-persistent-highlights-cache`

**Created**: 2026-09-01

**Status**: Ready

**Input**: 用户希望“精彩回顾”的最近五场和历史比赛数据首次获取后可以跨访问、跨服务重启复用；缓存应尽可能保存完整、可核验的比赛详情，并评估更多公开数据源补足缺失字段。

## User Scenarios & Testing

### User Story 1 - 再次进入立即看到精彩回顾 (Priority: P1)

用户第一次打开精彩回顾时可以看到明确的加载反馈；数据成功获取后，再次进入页面或服务重启后重新访问时，最近五场和历史区间结果应立即出现，不再重复经历长时间空白加载。

**Why this priority**: 最近五场是页面的主要入口，重复等待直接影响演示质量和基本可用性。

**Independent Test**: 首次访问最近五场并记录结果，重启服务、暂时断开外部数据源后再次访问；同一结果仍可快速显示，且不依赖新的外部请求。

**Acceptance Scenarios**:

1. **Given** 本地没有对应历史缓存，**When** 用户第一次打开精彩回顾，**Then** 页面展示一次清晰加载状态，成功后保存结果。
2. **Given** 已保存最近五场结果，**When** 同一用户或另一位已登录用户再次打开精彩回顾，**Then** 系统快速返回通用缓存，不重复等待外部数据源。
3. **Given** 服务已重启但持久数据未被删除，**When** 用户再次查询已保存的历史范围，**Then** 历史结果仍可读取。

---

### User Story 2 - 查看尽可能完整的比赛详情 (Priority: P1)

用户从精彩回顾选择一场比赛后，可以复用已保存的完整详情，包括最终比分、分节信息、领先球员、可用的比赛元信息和逐回合记录；缺失字段必须明确标记为不可用，不得推测。

**Why this priority**: 只有比分而没有详情会导致场馆、关键回合和战术分析等核心问题无法回答。

**Independent Test**: 对一场公开数据包含详情和逐回合的已结束比赛完成一次详情查询，随后断开外部数据源再次查询；详情字段和逐回合数量保持一致，且缓存不会被一个更不完整的响应覆盖。

**Acceptance Scenarios**:

1. **Given** 数据源返回比赛详情，**When** 系统保存该比赛，**Then** 保存所有已经过校验且对用户安全的可用字段，而不只保存卡片比分。
2. **Given** 已保存一份较完整的比赛详情，**When** 后续刷新只返回更少字段，**Then** 系统保留较完整的版本并更新可安全合并的字段。
3. **Given** 场馆、时长或完整战术记录不存在，**When** 用户询问该字段，**Then** 系统说明当前记录无法核验，不使用球队主场、常识或模型猜测补齐。

---

### User Story 3 - 缓存数据保持新鲜且不误导 (Priority: P2)

用户浏览已结束比赛时可以先看到缓存并由系统低频刷新；浏览今日或进行中比赛时则必须使用短时效数据，不能把历史缓存或过期比分当作今日实时结果。

**Why this priority**: 持久缓存提升速度，但不能牺牲实时比赛与今日赛程的正确性。

**Independent Test**: 分别准备已结束比赛缓存、今日赛程缓存和损坏缓存，验证历史缓存可先返回并刷新，今日缓存过期后必须重新核验，损坏记录被忽略且不会导致接口失败。

**Acceptance Scenarios**:

1. **Given** 已结束比赛缓存已超过刷新间隔，**When** 用户查询，**Then** 先返回可用缓存，并在不阻塞用户的情况下尝试更新。
2. **Given** 今日或进行中比赛缓存已过期，**When** 用户查询，**Then** 不返回过期结果，改为重新核验并展示必要的加载或错误反馈。
3. **Given** 缓存记录损坏、版本不兼容或校验失败，**When** 系统读取它，**Then** 忽略并隔离该记录，再走正常数据获取流程。

### Edge Cases

- 多个用户同时请求同一个未缓存范围时，只允许一次有效刷新写入，其他请求不得损坏数据库。
- 外部数据源失败但存在已结束比赛缓存时，历史回顾仍可使用，并保留原数据时间口径。
- 空赛程也是有时效的结果；历史空范围可以缓存，今日空结果不得长期复用。
- 同一比赛来自多个公开源但比分冲突时，不自动拼接矛盾数字；保留当前已核验版本并将刷新视为部分失败。
- 缓存目录不可写、磁盘空间不足或数据库锁定时，应用仍能退化到原有联网/内存路径。
- 用户登出不会清除通用赛事缓存；缓存不得保存密码、Cookie、会话、问题文本或模型提示词。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 将已结束比赛的最近列表、历史日期/区间结果和比赛详情保存为可跨进程重启读取的通用数据。
- **FR-002**: 系统 MUST 在缓存命中时优先返回已经过公开响应模型校验的数据，并避免新的外部数据请求。
- **FR-003**: 系统 MUST 对最近列表和过期历史缓存采用先返回、后刷新策略，同时合并并发刷新，避免重复外部请求。
- **FR-004**: 系统 MUST 对今日赛程、进行中比赛和未结束详情使用短时效策略；过期后不得作为当前事实返回。
- **FR-005**: 系统 MUST 保存数据版本、写入时间、新鲜截止时间、比赛状态、完整度和最近访问时间，以支持校验、刷新和清理。
- **FR-006**: 系统 MUST 保存每个已结束比赛中所有已校验且可公开展示的详情字段，包括可用的比分、球队、开赛时间、分节、领先球员、场馆/比赛元信息和逐回合记录。
- **FR-007**: 系统 MUST 防止更低完整度或字段冲突的刷新结果静默覆盖更完整的已核验详情。
- **FR-008**: 系统 MUST 对损坏、超限或版本不兼容的缓存记录执行失败关闭处理，不向用户返回未校验数据。
- **FR-009**: 系统 MUST 限制单条记录、总记录数和持久文件增长，并优先清理过期的非终场记录和长期未访问的派生列表。
- **FR-010**: 系统 MUST 在持久缓存不可用时退化到现有数据路径，不影响健康检查、认证和聊天主流程。
- **FR-011**: 系统 MUST 将缓存文件放在部署的持久存储中，使正常镜像重建和容器替换不会清除缓存。
- **FR-012**: 页面 MUST 仅在请求超过短暂感知阈值时显示加载状态；快速缓存命中不得清空已有内容或重复显示相同加载文案。
- **FR-013**: 系统 MUST 只接入可公开访问、结构化且能保留来源时间口径的数据源；覆盖不足的补充源只能补充非冲突字段，不能覆盖更可靠的比分或 PBP。
- **FR-014**: 系统 MUST 对数据源可用性、字段覆盖和冲突策略进行可复现验证；受网络区域限制或覆盖不足的候选源不得默认成为事实主源。
- **FR-015**: 缓存 MUST NOT 保存用户凭据、认证会话、聊天内容、模型密钥、提示词或其他用户级数据。

### Key Entities

- **赛事缓存记录**: 一个可公开展示响应的持久版本，包含稳定键、响应种类、数据版本、比赛状态、完整度、时间口径、新鲜截止时间、访问时间和有界负载。
- **比赛完整度**: 对比分、分节、球员统计、场馆/元信息和逐回合等可用字段的确定性计分，用于防止数据倒退。
- **刷新租约**: 对某个稳定缓存键的短时独占刷新状态，用于合并同一时刻的重复外部查询。
- **数据源能力记录**: 候选公开源在赛程、比分、场馆、球员统计和逐回合方面的覆盖与可用性结论。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 已有缓存的最近五场或历史范围在单机部署中 95% 的请求于 200 毫秒内返回，且外部数据调用次数为零。
- **SC-002**: 在服务重启和容器替换后，100% 的已保存终场比赛仍可读取，前提是持久存储未被主动删除。
- **SC-003**: 快速缓存命中时页面不出现可感知的空白加载；超过 250 毫秒的未命中请求才显示一次加载反馈。
- **SC-004**: 自动化用例证明今日/进行中数据过期后不会被当作实时事实返回，历史快照也不会冒充今日赛程。
- **SC-005**: 自动化用例覆盖缓存命中、首次未命中、过期后台刷新、重启复用、损坏隔离、并发访问和持久存储不可用七类场景。
- **SC-006**: 对同一比赛的完整响应和不完整刷新执行回归后，已保存详情字段数和 PBP 事件数不下降。
- **SC-007**: 数据源评估至少覆盖现有主源、NBA 官方公开数据端点和一个可访问的补充源，并记录可用性、字段覆盖及是否启用的结论。

## Assumptions

- 历史终场事实变化很少，但“最近五场”列表会随新比赛结束而变化，因此列表需要低频刷新而不是永久冻结。
- 第一版为单实例/单机演示部署；并发写入需要安全，但不要求跨多主机分布式一致性。
- 仅保存经过现有公开响应模型校验的数据；内部 Provider 原始响应和用户数据不进入持久缓存。
- 现有 ESPN 适配器继续作为主数据路径；候选补充源只有在当前部署网络可访问且覆盖经过验证后才启用。
- 对无法从可靠公开记录确认的场馆、时长或战术细节，保持“暂无可核验数据”优于推断填充。
